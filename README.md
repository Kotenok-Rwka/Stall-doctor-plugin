# 🩺 Stall Doctor

**Плагин для exteraGram, который находит, из-за чего лагает и зависает Telegram**

Следит за приложением в фоне и объясняет, почему оно тормозит или зависает: называет плагин-виновник и собирает отчёт, который можно отправить его автору.

## Возможности

- Замечает зависания интерфейса и обрывы связи и записывает, что в это время происходило.
- Называет плагин, из-за которого это случилось: смотрит потоки, лог Android и ошибки.
- Показывает утечки потоков и нагрузку на процессор от конкретных плагинов.
- Перезагружает плагины, если всё встало. Умеет искать виновника делением списка плагинов пополам.
- Делает короткий или полный отчёт для разработчика плагина. Сообщения, номера телефонов и адреса прокси в отчёт не попадают.
- Хранит историю зависаний, сводку «здоровья системы» и экспорт настроек.

## Установка

### Как каталог (рекомендуется)

1. В exteraGram включите **Unknown sources** (плагины из Git считаются неизвестными источниками).
2. Добавьте каталог плагинов и вставьте URL этого репозитория:
   `https://github.com/Kotenok-Rwka/Stall-doctor-plugin`
3. Установите **Stall Doctor** из списка.

### Вручную

Скачайте [`plugins/stall_doctor.py`](plugins/stall_doctor.py) и откройте его в exteraGram как `.plugin` (это тот же Python-код).

## Почему при установке есть предупреждения

exteraGram автоматически проверяет код плагина и ругается на всё, что похоже на опасное. Здесь предупреждения вызваны самой задачей плагина:

| Предупреждение | Зачем это нужно |
|---|---|
| Запросы и интернет | Плагин замеряет, как отвечает сервер Telegram: смотрит на сетевые запросы приложения и сам отправляет служебный пинг `updates.getState` в сам Telegram. Больше никуда ничего не отправляется. |
| Настройки приложения | Для перезагрузки плагинов он обращается к менеджеру плагинов и конфигу exteraGram. |
| Влияние на другие плагины | Он ставит хуки на методы приложения. Без этого нельзя узнать, кто именно подвесил интерфейс. |

В коде нет обращений к сторонним серверам, автообновления нет. Опасные действия (прерывание потоков, перезагрузка) включаются отдельной настройкой или по вашей кнопке. Код открыт, его можно прочитать перед установкой.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `plugins/stall_doctor.py` | Сам плагин |
| `extera-plugins.json` | Индекс каталога (schema 1), собирается автоматически |
| `tools/build_index.py` | Сборка индекса и проверка метаданных |
| `tools/device_test.py` | Проверка на телефоне через DevServer (`adb`, порт 42690). На настоящем устройстве не запускался |
| `tests/run_tests.py` | Регрессионные тесты на заглушках SDK. Проверяют логику, но не заменяют проверку на устройстве |
| `tests/test_device_script.py` | Тест клиента DevServer на поддельном сервере и разбора лога |
| `.github/workflows/index.yml` | CI: тесты и пересборка индекса при изменении плагина |

## Разработка

Проверка перед выпуском:

```bash
python3 -I tests/run_tests.py
python3 -I tests/test_device_script.py
python3 -I tools/build_index.py
python3 -I tools/device_test.py   # телефон по USB, включён режим разработчика плагинов
```

Выпуск обновления: правьте `plugins/stall_doctor.py` и поднимайте `__version__`. После пуша в `main` GitHub Actions прогонит тесты и сам обновит `extera-plugins.json`.
Для этого включите **Settings → Actions → General → Workflow permissions → Read and write**.
